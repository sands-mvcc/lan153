If You Can't See It, You Can't Secure It

Attackers live in environments that lack visibility. This lesson builds the SecOps mindset: baselining normal behavior, cataloging every asset, and turning log noise into actionable alerts — before an unknown device becomes a breach.

Learning Objectives
  • 1Define system baselines and explain how drift detection identifies anomalies
  • 2Build and maintain an asset inventory using discovery techniques and CMDB principles
  • 3Distinguish log types (event, system, security, application) and configure SIEM alert thresholds
  • 4Explain the role of sandboxing in safe malware analysis and unknown-file detonation
  • 5Apply continuous monitoring principles to detect rogue devices and policy violations
  • 6Map SecOps controls to CompTIA Security+ SY0-701 exam objectives

Key Terms — 8 Core Concepts
Baseline
A documented snapshot of a system's normal, secure configuration state
Drift
Any deviation from the established baseline — authorized or otherwise
Asset Inventory
A comprehensive register of all hardware, software, and data assets on the network
CMDB
Configuration Management Database — authoritative source of asset truth
SIEM
Security Information & Event Management — aggregates logs and fires alerts
IoC
Indicator of Compromise — forensic evidence that an intrusion has occurred
Sandbox
Isolated execution environment for safely detonating suspicious files
Rogue Device
An unauthorized device connected to the network — internal or external origin
🔌 Opening Scenario — The New Laptop on the Network

At 2:47 AM on a Tuesday, a DHCP lease is assigned to a device no one in IT recognizes. The MAC address doesn't match any entry in the asset inventory. Within 12 minutes, the device queries the Active Directory LDAP server, attempts three failed SMB connections to the file server, and downloads 847MB of data before going offline. By 9 AM, no one in IT knows this happened — because no alert was configured.

Discussion questions: What monitoring controls would have detected this? What should have triggered an alert? What does an attacker gain by operating at 2:47 AM specifically?

Obj 4.3 — Configuration Mgmt

System Baselines & Drift Detection

A baseline documents every measurable aspect of a secure system: open ports, running services, installed software, local user accounts, registry keys, and file hashes. Once established, any deviation — planned or unplanned — is drift.

  • CIS Benchmarks — Community-consensus hardening guidelines by OS/platform
  • STIG — DoD-mandated Security Technical Implementation Guides
  • FIM — File Integrity Monitoring alerts on unauthorized file changes
  • Authorized Drift — Documented, approved change (e.g., patch deployment)
  • Unauthorized Drift — Unexplained deviation — potential compromise indicator
Real-World AnalogyA newly renovated hotel room has a "standard setup" photo. Housekeeping compares the room to the photo each morning. Any difference — missing towels, moved furniture — triggers an investigation.
📚
Obj 4.3 — Asset Management

Asset Inventory & Discovery

You cannot protect what you don't know exists. Every connected device is an attack surface. Asset inventory combines automated discovery with a maintained Configuration Management Database (CMDB).

  • Active Discovery — Nmap, Nessus scans that probe the network
  • Passive Discovery — DHCP lease analysis, traffic monitoring
  • CMDB — Authoritative register of all Configuration Items (CIs)
  • NAC — Network Access Control enforces policy for unknown devices
  • 802.1X — Port-based authentication prevents rogue device connectivity
Library Catalog AnalogyEvery book in a library has a catalog record. An uncataloged book cannot be found, cannot be checked out, and may be stolen without anyone knowing. The CMDB is your catalog — every uncatalogued asset is a hidden liability.
📊
Obj 4.4 — Logging & Monitoring

Log Management & SIEM Architecture

Logs are the security camera footage of your infrastructure. A SIEM aggregates logs from across the environment, normalizes formats, correlates events across systems, and fires alerts when patterns exceed thresholds.

Event IDMeaning
4624Successful logon
4625Failed logon attempt
4648Logon with explicit credentials
4720User account was created
Real-World AnalogyA casino surveillance system doesn't record everything with equal priority — it has motion sensors, face recognition triggers, and a security team that only responds when the system flags anomalies. SIEM is your casino surveillance for the network.
📦
Obj 4.6 — Malware Analysis

Sandboxing & Safe File Detonation

A sandbox is an isolated execution environment where suspicious files can run freely and reveal their behavior without risk to production systems. Sandboxing bridges the gap between static signature detection and behavioral analysis.

  • Static Analysis — Examine file without executing (strings, hash, PE header)
  • Dynamic Analysis — Execute in isolation; observe network calls, registry changes
  • VM-based — Cuckoo Sandbox, Any.run — full OS isolation
  • Cloud-based — VirusTotal, Hybrid Analysis — community intelligence
  • Anti-Sandbox — Malware that detects VM environments and stays dormant
Bomb Disposal AnalogyA suspicious package isn't opened in a crowd — it's taken to a blast-proof containment room. Analysts observe the detonation safely, then extract forensic evidence. A sandbox is the blast-proof room for suspicious files.
