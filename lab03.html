Stage 1 of 6 LO1 · Foundations of encryption

XOR: The Building Block

Every byte of plaintext can be combined with a key byte using the XOR (exclusive-OR) operation. XOR is reversible: applying the same key a second time restores the original data. This is the mathematical seed that real ciphers build on — and, used alone, one of the weakest.

Hint: why does re-applying XOR decrypt it?

XOR has the property A ⊕ K ⊕ K = A. Encrypting is ciphertext = plaintext ⊕ key. Decrypting is plaintext = ciphertext ⊕ key — the exact same operation, run again with the same key.

Symmetric Encryption with AES-256

Modern symmetric encryption (AES, the current NIST standard) uses one shared secret key for both encryption and decryption. It's fast and well suited to bulk data — but both parties need the exact same key beforehand, which raises the key-distribution problem you'll solve in Stage 4.

Hint: what is the IV for?

The initialization vector randomizes each encryption so that encrypting the same message twice with the same key never produces the same ciphertext. It doesn't need to be secret, but it must never be reused with the same key.

Stage 3 of 6 LO2 · Cryptographic hashing & integrity

SHA-256: Fingerprinting Data

A cryptographic hash function takes input of any size and produces a fixed-length "fingerprint." A secure hash is one-way (you can't reverse it to get the input back), deterministic (same input always gives the same output), and exhibits the avalanche effect — a tiny change in input produces a wildly different hash.

Hint: what does this prove about integrity?

If a published hash and a locally-computed hash of a downloaded file don't match, the file was altered or corrupted in transit — that's how software vendors let you verify updates haven't been tampered with.

Stage 4 of 6 LO1 · Asymmetric encryption

RSA: Solving Key Exchange

Asymmetric (public-key) encryption uses a mathematically linked key pair. Anything encrypted with the public key can only be decrypted with the matching private key. The public key can be shared openly — even over an insecure channel — which is exactly the problem symmetric encryption couldn't solve on its own.

Hint: why not just use RSA for everything?

RSA is far slower than AES and can only encrypt small amounts of data at once. In practice, systems like TLS use RSA (or similar) just to securely exchange a symmetric AES key, then switch to AES for the actual bulk traffic — this hybrid approach is why HTTPS is both secure and fast.

Stage 5 of 6 LO3 · Digital signatures

Digital Signatures: Proof of Origin

A digital signature flips the RSA key pair around: you sign a message's hash with your private key, and anyone can verify it with your public key. A valid signature proves three things at once — authentication (it came from you), integrity (it wasn't altered), and non-repudiation (you can't credibly deny signing it).

Verification recomputes the hash of the message you provide and checks it against what the signature guarantees. Any change in the message produces a different hash, so it no longer matches what was signed — the same avalanche effect from Stage 3, now used to catch tampering.
