01

Capture Filters vs. Display Filters

Wireshark has two unrelated filter languages. Mixing up their syntax is the most common beginner error — a display filter typed into the capture-filter field will simply be rejected.

Display Filters

Applied after the capture, in the filter bar. Narrow down what you're looking at — nothing is discarded.

  • Field-based: protocol.field
  • Can be changed anytime, as often as you like
  • Turns green when valid, red when invalid, yellow when unusual but technically legal
tcp.port == 443 && ip.addr == 10.10.5.20

Capture Filters

Applied before you start capturing, using Berkeley Packet Filter (BPF) syntax. Packets that don't match are never recorded.

  • Keyword-based: host, port, net
  • Locked in once capture starts — set once, capture, then stop
  • Use when the capture would otherwise be too large to store
tcp port 443 and host 10.10.5.20

Attack Signature Quick Reference

The six incident types from the SOC Analyst Simulator, and the filter that isolates each one fastest.

1 Port Scan / Recon

One source, many destination ports, each connection ending before real data ever moves.

Isolate the probestcp.flags.syn==1 && tcp.flags.ack==0
Then narrow to one hostip.src == 10.10.10.16
2 ARP Spoofing

The same IP address answered "is at" by two different MAC addresses — especially unsolicited replies.

Wireshark's built-in checkarp.duplicate-address-detected
Manual reviewarp
3 Brute Force Login

Rapid-fire USER/PASS pairs from one source, mostly ending in a failure code.

Every credential attemptftp.request.command == "PASS"
Just the failuresftp.response.code == 530
4 DNS Spoofing

Two answers for the same query and transaction ID, resolving to two different addresses.

All name resolutiondns
Isolate one transactiondns.id == 0x4a2f
5 SYN Flood (DoS)

A single destination flooded with SYNs from many unrelated source addresses, none completing.

Same base filter as a scantcp.flags.syn==1 && tcp.flags.ack==0
Pin it to the victimip.dst == 10.10.5.20
6 On-Path Credential Sniffing

A login submitted over plain HTTP — readable the moment traffic passes through an attacker's relay.

Find the login POSThttp.request.method == "POST"
Confirm cleartext credshttp contains "password"

Field Notes

Green means valid, not "true"A green filter bar only means the syntax parses — it can still legitimately match zero packets.
Right-click, then "Apply as Filter"Faster and less error-prone than typing a field name from memory.
Build filters incrementallyStart broad (arp), then add clauses with && once you see what you're looking at.
Quotes matter for stringshttp.request.method == "POST" needs the quotes; numeric and IP comparisons don't.
Save frequent filtersThe bookmark icon on the left of the filter bar stores one for reuse across captures.
A busy capture? Stack conditionsip.addr==X && tcp.port==Y && tcp.flags.syn==1 narrows fast.
